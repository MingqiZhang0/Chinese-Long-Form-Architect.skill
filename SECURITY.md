# Security Policy

This is a research preview, not a security boundary or a hardened database service. A project's writer-facing context is governed by declared visibility and source trust, not a sandbox against arbitrary hostile plugins or agents. The workbench's read-only restrictions are application-level; they are not an OS isolation guarantee.

Please avoid publicly reporting any live secrets, private manuscript material, or step-by-step exploitation against other users. To report a security issue privately, contact the repository maintainer through GitHub's private vulnerability-reporting feature after it is enabled. Until then, avoid posting sensitive details in issues; use a private communication channel agreed with the maintainer.

Do not publish raw project archives, author transcripts, credentials, or model session logs as bug reproductions. Reduce to synthetic fixtures first.
