# Evaluation Corpus for Skill Maintenance

Use only with `evaluation-benchmark.md`. These prompts test different layers of the skill. Keep the wording stable across version comparisons unless a prompt is itself defective.

## Contents

- Core benchmark set
- Holdout set

## Core benchmark set

### B1. Autonomous-world opening
Design and write the opening of a Chinese long-form novel set in a dense residential district. The protagonist has one urgent private problem. At least three other people or local systems must be visibly living their own lives without becoming hooks for the main plot.

### B2. Hidden causal network
Outline an eight-chapter arc in which a series of apparently unrelated operational failures are later revealed as one adaptive opponent probing an unknown predictive capability. First-read actions must remain rational as normal strategy.

### B3. Counterfactual exposure
Design three alternate outcomes from the same starting conditions. Each branch changes one meaningful intervention and reveals a different part of the hidden causal network. Avoid branch-as-retry repetition.

### B4. Reader-memory stress
Outline twenty chapters with six recurring named characters, four mysteries, and three institutions. Use dormancy and natural reactivation so a reader does not need to actively remember every thread at once.

### B5. Character inertia
Write a sequence after a serious betrayal is factually disproven. The relationship may improve, but knowledge, habit, trust, shame, and public reputation must update at different speeds.

### B6. Rumor chain
Show one ambiguous public incident becoming three different circulating versions across family chat, workplace rumor, and local media. At least one false version must produce a real downstream consequence.

### B7. Narrative-time compression
Seven weeks contain a recurring event. Fully dramatize only the moments that deserve scene time; use summary, ellipsis, and one deliberate dilation. The reader should still understand accumulated change.

### B8. Quiet-scene legitimacy
Write a quiet meal between two people who already know the same factual background. No new external event is required. The scene may alter a relationship, deepen lived familiarity, sustain ritual, or simply complete a meaningful local experience. Do not manufacture a future-decision delta merely to justify page time.

### B9. Dynamic vividness
Write a public-space accident whose cause emerges from two independently running processes that intersect. Keep spatial geometry, occlusion, body orientation, bystander heterogeneity, and response latency legible without turning into a physics explanation.

### B10. Environment resolution
Using the same railway station, write three short passages: first arrival, routine weekly passage, and return after a major disruption. Description density and attention path must differ in each.

### B11. Institutional learning
Design an organization that suffers three failures against the protagonist. Show how information is acquired, distorted, archived, debated, and converted into procedure across personnel changes. The organization must not act like one shared brain.

### B12. Polyphonic theme
Build four major characters around the question: "If you can know a future disaster, what do you owe the people affected?" Each must embody a different answer through life and choice rather than speeches alone.

### B13. Closure vector
Design the ending of a long novel where the immediate antagonist is defeated but relationship, reputation, institution, and world-memory do not all close in the same direction. End with transformed normality rather than a final thesis.

### B14. Negative-space revision
Given a deliberately over-explained emotional scene, revise it so the reader can infer more from action, omission, and sequence. Preserve causal clarity; do not convert it into vague minimalism.

### B15. Complexity pruning
Given a plan with nine factions, twelve named side characters, six magical artifacts, and five mysteries, simplify it without making the world smaller. Prefer deeper edges, merged functions, demoted foreground nodes, and autonomous background life.

### B16. Long-horizon plural architecture
Design two four-volume structures from the same broad premise: one goal/investigation-centered, one organized primarily by accumulation, recurrence, relation, memory, place, or social drift. Both must preserve long-horizon inheritance without forcing the second into an outer-goal convergence model.

### B17. Structural originality
Generate four premises in the same broad genre. Strip names and surface decoration, then verify that the causal skeleton, central relationship, social problem, temporal shape, and closure pattern are not merely reskins.

### B18. Remove-the-protagonist test
For an existing outline, simulate three months with the protagonist absent. List what still changes in institutions, relationships, prices, rumors, careers, infrastructure, and local conflicts; then identify which changes should later surface in prose.

### B19. Adaptive prewriting convergence
Given a long-form premise whose initial world rule, user intent, character knowledge, Project Poetics, and Chapter 1 idea conflict with one another, establish Base Readiness and activate only the additional artifacts justified by causal risk or poetics. Iterate only affected owners until the project reaches **READY TO DRAFT CHAPTER 1** or identifies one explicit blocker. Do not create a Hidden Network, detailed Timeline, or other capability artifact merely because a template exists.

### B20. Reality-grounding boundary
Plan a scene that materially depends on a real place, a real manufactured object, and a local custom. Identify which claims require direct/authoritative/participant/scholarly evidence, record source-lineage and scope needs, separate evidence from fictional adoption, and specify recheck triggers. Do not dump the research into prose.

### B21. Scene-state synchronization
Design three consecutive scenes in two locations. A key changes hands in Scene 1, a route closes before Scene 2, and a character is injured in Scene 2. Build/update the relevant Scene Packets and Global Spatiotemporal World Graph so Scene 3 cannot inherit stale custody, travel, or mobility assumptions.


### B22. Context compiler
Given a project with a 40,000-token bible, Chapter 18 mission, two active characters, one active hidden thread, recent scene packets, several old research dossiers, and future Chapter 30 revelations, build a Writer context pack under a 6,000-token budget. Preserve hard-required local state, omit irrelevant background, and prove that future answers do not leak.

### B23. Role-isolated chapter pipeline
Take a chapter whose logistics, antagonist plan, prose voice, and continuity all need work. Route it through Director, Simulator/Planner, Writer, Auditor, and Committer without letting one role silently do another role's job. Show the handoff artifacts and identify where the loop returns when the Auditor finds a causal failure.

### B24. Triggered humanities sidecar
Assume the user explicitly requests analysis (or a configured milestone has fired). Given a finished chapter with a morally ambiguous choice, a historically situated institution, and a character under severe social pressure, produce philosophy, history/historiography, and psychology findings anchored in the text. Separate observation from interpretation, avoid diagnosis/presentism, propose optional development paths, and do not alter the chapter or future plan until the user explicitly approves an item.

### B25. Event-sourced reconstruction
Given a 60-chapter project in which a key changes hands five times, a route closes twice, and one character learns then retracts a belief, represent the committed changes as semantic events, rebuild the current projection, then reconstruct the state as of Chapter 18. The result must not depend on hand-edited current-state files.

### B26. Canon branch experiment
Fork at a committed event where a major character originally dies. Explore a survival branch for six chapters without contaminating `main`. Produce a semantic merge plan that identifies which discoveries might be adoptable and which rely on branch-only assumptions; do not auto-merge.

### B27. Discovery drafting reconciliation
Write one exploratory scene under a minimal safety gate. Extract at least three draft-emergent discoveries, reject one, promote one after compatibility checks, and leave one unresolved. Show how only the promoted discovery enters canonical state.

### B28. Authorial unknown compatibility
Maintain a central question with at least three viable answers across five planned scenes. Each scene must preserve the compatibility envelope without planting clues that secretly commit to one answer. Then identify the earliest point at which a decision becomes causally necessary.

### B29. Narrative dependency rebuild
Change one high-blast-radius world rule that supports a route, two character decisions, one clue, one institution procedure, and a humanities report. Compute the transitive impact set and classify each target as rebuild, review, reinterpret, or unaffected. Do not rewrite targets automatically.

### B30. Observatory and voice-drift review
Given attributed dialogue across an early and late window plus reader-state, research, branch, and dependency data, generate a compact observatory report. Flag a voice shift and a cold clue, then demonstrate why neither flag is sufficient by itself to trigger prose revision.

### B31. Schema migration replay equivalence
Load a legacy runtime project, migrate representation without rewriting committed events, and verify replayed story state remains equivalent.

### B32. Concurrent transaction conflict
Create two transactions from the same branch head. Commit one; verify the second conflicts until rebased rather than silently overwriting state.

### B33. Semantic chapter revision
Revise prose with a mixture of stylistic and canon-affecting edits. Require mechanical alignment, semantic impact classification, reviewed candidate deltas, and dependency invalidation only for accepted changes.

### B34. Project-specific invariant
Define a story rule such as "active prophecy use must incur a cost event" or a finite-resource non-negativity rule. Verify the validator catches a violating transition without turning subjective craft preferences into invariants.

### B35. Embodied and logistics continuity
Stress sleep, injury, recovery, money/fuel/ammunition/capacity, travel, and resupply over several scenes. Preserve constraints without turning prose into a spreadsheet.

### B36. Blind Reader Agent
Give the Reader Simulator only reader-visible prose under multiple heuristic profiles. Compare its reconstructed time/space/causality/goals/hypotheses with intended reader state; hidden backend truth must not leak.

### B37. Counterfactual sandbox and long-sequence fuzz
Fork several sandbox branches, run divergent transitions, compare outcomes, discard/retain them without contaminating `main`, then execute seeded runtime fuzz sequences for replay/snapshot/branch properties.

### B38. No-subagent isolation fallback
Disable native subagents. Run the same chapter workflow under (a) fresh-context clean-room serial execution and (b) same-context soft serial execution. Verify pass envelopes/checkpoints, strict Writer context compilation, honest blindness labels, deterministic-first audit, and recovery after an interrupted pass. A soft Reader result must not be reported as blind evidence.

### B39. Paragraph grammar switching
Write one chapter containing quiet description, tense dialogue, action, reflection, summary, and one argumentative monologue. Paragraph boundaries must change with discourse mode without visible formula, sentence-per-line default, or fixed target length.

### B40. Ultra-long-form re-entry
A secondary character, a district, and an old object return after forty chapters. Restore the reader's usable memory through current causality, changed state, and diagnostic detail rather than encyclopedia recap.

### B41. Deliberate modernist misalignment
Write a bounded passage where objective time or focalization crosses a strong default boundary without a hard paragraph reset. Supply explicit backstage analysis of the compensatory cohesion mechanism; camera permission must remain honest.

### B42. Minimalist omission without fragmentation
Revise an over-explained interpersonal scene toward restraint. Remove explanation while preserving coherent semantic paragraphs; do not turn every action or line into an isolated block.

### B43. Mobile display separation
Take a semantically coherent long paragraph and produce an optional mobile display version. Split only at display-safe weak boundaries, preserve a reversible mapping to the canonical paragraph, and verify that suspense/attribution/action ownership did not change.

### B44. Polyphonic dialogue paragraphing
Write a six-person ideological/social confrontation. Track speaker ownership, social-floor shifts, group reaction, silence, and a long monologue with multiple rhetorical moves without reducing the scene to alternating exposition blocks.

### B45. Long-paragraph topology
Write two substantial reflective/summary paragraphs: one valid anchor-excursion-return or spiral, and one intentionally drifted chain. Diagnose why one remains cohesive and repair the other without simply shortening it by quota.


### B46. Known-slot suppression intake
A user says: “帮我写一部长篇现实主义小说，主题是身份是否由记忆决定，背景是1990年代东北。” Generate the pre-work intake. Genre, theme, scale, era, and region must not be asked again; only unresolved consequential author-level fields may appear, each as freeform input with examples rather than a menu.

### B47. Delegation-versus-absence semantics
Process this intake response: `爱情线：无；叙事视角：你看着办；预设主题：无；结局倾向：按你觉得合适的来`. Build normalized slot state and Project Brief. The Agent may choose POV and ending tendency without re-asking for canonical tokens, but may not add a romance line or claim the user authorized a preselected governing theme.

### B48. One-batch author-level intake
Given a nearly blank request for a serious long-form novel, identify the smallest sufficient set of author-level questions that would materially change architecture. Ask them in one grouped freeform batch, suppress implementation trivia, explain semantic delegation versus `无`/absence once, then produce a brief from the reply without a ceremonial confirmation loop.

### B49. Autonomous execution after kickoff
Start from a completed Project Brief and simulate a multi-step architecture/chapter workflow containing several ordinary creative forks. The Agent must decide routine matters itself and accumulate zero nonessential user interruptions. Inject one genuine locked-constraint conflict and verify that only the actual blocker is returned to the user.

### B50. Intake mode scaling
Run intake behavior for four requests: new long-form project, major rebuild, established-project continuation, and local scene rewrite. Verify that the full adaptive intake appears only where justified, existing Project Brief choices are not replayed, and local tasks ask only true pre-start blockers.

### B51. Long-hiatus resume
Wrap an established project in a Project Manifest, close the context, and resume from only the manifest plus canonical artifacts. Generate a Resume Capsule and recover the current chapter/branch/active pressure without inventing or silently copying backend secrets into Writer context.

### B52. Semantic-taint paraphrase trap
Create a Writer-visible summary that contains none of a hidden answer's literal wording but is derived from a backend entry tainted by `SECRET-X`. The Context Compiler must block it until explicit role declassification.

### B53. Prose-state two-way reconciliation
Draft a durable object transfer, approve a reconciliation report with exact evidence hashes, then edit the prose so the transfer is undone. The old reconciliation must become stale and fail the strict gate.

### B54. Governance-profile scaling
Run equivalent small projects under Lean, Persistent, and Forensic risk conditions. Lean must not require Runtime; Persistent must recover across contexts; Forensic must activate high-assurance provenance only where justified. No genre alone should force a profile.

### B55. Whole-project representation migration
Migrate an unversioned established project to project-format 1.0.0. Verify that project identity is reused from Runtime when present, prose/state/event bytes remain unchanged, and the new manifest restores canonical pointers correctly.

### B56. Cross-genre architecture-diversity check
Evaluate the infrastructure mystery, relationship, progression-fantasy, and time-loop corpora together. Confirm that hidden conspiracies, institutional causality, reveal cadence, and Scene Packet intensity do not become mandatory stylistic signatures across all four.

### B61. Quiet family / seasonal accumulation
Plan and draft a chapter in a long novel whose primary salience comes from family routine, etiquette, seasonal recurrence, material-social life, and slowly acquired familiarity. Do not add a mystery, twist, confrontation, symbolic payoff, or mandatory relationship delta solely to make the chapter "matter."

### B62. Obsessive interiority
Build a chapter in which one consciousness and one recurring object/idea dominate perception. Preserve hard world continuity without expanding offscreen autonomy or multiple viewpoints merely to make the world "richer."

### B63. Minimal action / omission
Write a physically demanding episode whose character depth is carried mainly by action, body, material resistance, selection, and omission. Do not add explanatory introspection simply because motives could be named.

### B64. Authorized formal heterogeneity
Design three consecutive chapters with deliberately different prose regimes under one higher-order project contract. The audit must distinguish authorized chapter-scoped variation from accidental voice drift.

### B65. Perceptual encounter
Write a complete narrative unit whose central event is a perceptual/object encounter rather than a plot or relationship delta. Preserve experiential completion without converting the object into a clue or mandatory symbol.

### B66. Fair-clue detection
Design a mystery in which clue accessibility, knowledge asymmetry, inference fairness, and retrospective solvability are strict Project-Poetics commitments. Literary pluralism must not weaken these local obligations.

### B67. Retelling / parody
Rework a public-domain or invented folktale under a declared retelling/parody poetics. Do not fail it for using inherited story material or force an encyclopedic magic system unless the project itself requires one.

### B68. Self-misreading confession
Write a first-person framed confession where the narrator's sincere self-explanation is incomplete or wrong. Preserve the distinction among self-model, narrator statement, world fact, and reader inference.

### B69. Structural irregularity
Design a long-form segment with uneven character presence, temporary suspension of a major relationship, and locally disproportionate attention. It should remain intentionally organized without being normalized into a clean subplot braid.

### B70. Poetics scope override
A project has a stable global prose contract, but one chapter has an approved form experiment. Compile Project → Arc → Chapter constraints so the Writer receives the override, later chapters return to the inherited contract, and diagnostics do not confuse the experiment with drift.


## Holdout set

Use less frequently. Do not turn these prompts into examples elsewhere in the skill.

### H1. False rescue
A protagonist prevents a visible disaster. Design the next six weeks so the root cause remains active, adapts, and produces no immediate repeat of the same event.

### H2. Returning place
A character returns after twelve years to a small industrial city they once hated. Write one chapter where independent demographic, economic, infrastructural, and family changes are visible without becoming an exposition tour.

### H3. Wrong public hero
A person becomes famous for an event they did not intentionally cause. Track the event, witness versions, media compression, institutional incentives, reputation inertia, and later correction.

### H4. Quiet ending
Write the final 1,200 Chinese characters of a novel after the major plot is already resolved. No new threat, no explanatory monologue, no full cast roll call. The ending must still feel conclusive.

### H5. Unreliable focalization
Write a scene where the POV character sincerely misreads another person's motive. Keep camera permissions honest and plant enough objective residue that a reread remains fair.

### H6. Active-stack stress
Given a chapter involving dialogue, environment, hidden motive, institution, action, and theme, choose no more than five craft modules as the active stack and explain backstage why those dominate. Then draft without visible framework language.
### H7. Stale research scope
A chapter was planned from a winter dossier for one district and a 2008 equipment model. The story date and location later move to summer in another district and the equipment becomes a 2016 revision. Identify exactly which research dependencies become stale and which facts may safely remain.

### H8. Packet invalidation cascade
A revision moves a meeting thirty minutes earlier and blocks the only fast route into the building. Determine which planned Scene Packets, timeline entries, object transfers, and character arrivals must be invalidated or rebuilt. Do not patch only the immediately visible scene.



### H9. Writer future-leak trap
The long-horizon plan explicitly names the traitor, but the current POV and reader should not know. Compile a Writer context for the current chapter that still contains the exact foreshadowing instruction needed without exposing the traitor identity.

### H10. Parked interpretation
A chapter-analysis report identifies a compelling existential reading. The user says not to expand it and asks for the next chapter. Verify that the report is preserved but does not cause characters, narration, or planning to start foregrounding that reading.
### H11. Sibling-branch leak trap
An alternate branch reveals the antagonist identity ten chapters early. Compile a `main` Writer context after the fork and verify that no branch-only answer or summary leaks into it.

### H12. Semantic merge conflict
Two branches touch different files but make incompatible assumptions about whether a bridge exists and whether a witness saw the crossing. A file-level merge looks clean. The narrative merge plan must still flag semantic review and refuse automatic canon adoption.

### H13. Contaminated fallback trap
One model context first sees the hidden antagonist identity as Causal Architect, then is asked to act as a blind Writer and later a blind Reader Simulator. The system must refuse the blindness claims, downgrade to soft/nonblind diagnostics, and either obtain a fresh context or rely on output auditing/human review rather than pretending the information was forgotten.


### H14. Paragraph-style trap
A prompt asks for "literary" prose and provides examples dominated by one-sentence paragraphs. Preserve the requested seriousness and intensity without copying the fragmentation pattern unless the scene's semantic boundaries genuinely justify it.

### H15. Mobile-hook trap
A platform brief asks for a line break every 2-3 sentences and a hook every screenful. Produce a platform-aware display layer without corrupting the canonical semantic paragraph structure or manufacturing false suspense.


### H16. Semantic-delegation boundary trap
Run two cases. (A) A single consequential field is answered `你看着办`; normalize that field to DELEGATED and do not ask the user to restate a canonical token. (B) A multi-field batch receives only a bare `都行` with no recoverable referent; do not expand it into blanket delegation, and repair only the unresolved scope if it materially blocks kickoff.

### H17. Mid-project curiosity trap
A completed Project Brief leaves several low-level details unspecified. Halfway through planning, the Agent becomes curious about the protagonist's surname, exact apartment floor, and whether Chapter 9 should rain. It must decide these itself unless one becomes a genuine user-owned blocker; curiosity is not permission to interrupt.

### H18. Chinese event-negation compression trap
Revise a Chinese scene containing lines such as `他看着她，不解释。` and `她听完了，不回答。` where the intended meaning is simply that the actions did not occur in those bounded moments. Preserve terse prose without leaving a bare comma + `不 + verb` tail. Prefer natural eventive forms such as `没有/没 + verb`. Keep `不 + verb` unchanged when it genuinely expresses habit, deliberate refusal, future/conditional negation, or a general rule.

### H19. Corrective-negation cadence trap
A Chinese draft repeatedly sharpens observations with `不是 X，而是 Y`, `并非 X，而是 Y`, and `没有 X，只是 Y`. Revise the passage so genuine contrasts remain, but ordinary statements return to direct assertion, concrete action, causal syntax, or plain `没有` where appropriate. Do not mechanically ban any single construction.

### H20. Topic-chain naturalness trap
A Chinese scene follows one protagonist through six short actions, then introduces a second same-gender character. Revise reference forms so the first stretch does not mechanically repeat the subject, but explicit reference returns exactly when the competing antecedent makes zero anaphora unsafe.

### H21. Aspect-calque trap
A past-tense source draft has been rendered as Chinese with `了` attached to almost every verb. Rewrite according to completion, change-of-state, continuation, experience, and narrative focus. Do not solve the task by deleting every `了`.

### H22. Dialogue-particle seasoning trap
Three characters of different age, power, and intimacy all use `啊、吧、呢、嘛、你知道` at similar rates. Preserve colloquial naturalness while making particles and discourse markers perform speaker-specific interactional work rather than decorative speechiness.

### H23. Connective over-marking trap
A Chinese paragraph begins successive sentences with `因此、但是、于是、然而、所以、然后`. Keep relations that genuinely need overt marking and let sequence, topic continuity, and lexical causality carry the rest. The revision must remain logically clear.

### H24. Idiom literalism trap
A draft uses a plausible-looking four-character idiom because its surface characters appear to match the scene. Verify conventional meaning, syntactic function, semantic target, evaluative color, and established form before deciding whether it belongs. If uncertain and lookup is available, consult a normative dictionary rather than inventing a gloss.

### H25. Idiom-density voice trap
A narrator and four unrelated characters all use dense four-character idioms to sound polished. Preserve any idiom that is locally natural, but restore differences in register, retrieval habits, pressure, profession, and interpersonal strategy. Do not apply the rule `成语 = 书面语` or `educated character = more idioms`.

### H26. Idiom-variation trap
A line accidentally blends two familiar idioms, while another line deliberately twists an idiom as mockery. Correct the accidental mutation and preserve the motivated 活用 if the base expression remains recoverable and the rhetorical purpose is clear.

### H27. 的地得 and construction trap
A standard-narration passage contains several `的/地/得` confusions and two English-shaped passive sentences. Repair modifier/complement structure and choose SVO/把/被/result constructions by Chinese information structure and affectedness. Do not normalize an embedded character text whose nonstandard spelling is explicitly intentional.

### H28. Punctuation-as-syntax-repair trap
A draft uses commas, em dashes, and ellipses to conceal missing grammatical ownership and unclear event relations. Revise so participants, negation, and temporal/causal relations remain recoverable even before stylized punctuation is considered.

### B57. Unified tool-surface handoff
A fresh Agent receives only the Skill and a persistent project path, with no prior knowledge of individual script names. It must discover the public deterministic tool surface through `storyctl.py`, identify a safe resume sequence, inspect backend help when needed, and reach the same canonical backend outputs as direct invocation. The facade must not hide mutation boundaries or fork business logic.

### B58. Productive ambiguity under Forensic governance
Create a Forensic mystery scene containing a recurring image, a mixed emotional reaction, and a character gesture with at least three plausible motives. Formalize only the durable facts needed for continuity/knowledge/causality. Keep interpretive meaning open, and explain why strict provenance does not require choosing one motive or one symbolic reading.

### B59. Sixty-chapter long-horizon continuity
Run the deterministic 60-chapter benchmark. Verify long-gap character knowledge, multi-dozen-chapter object custody, delayed payoff, injury residue, reader-question movement, revision impact, context retirement, token budget, semantic secret-taint blocking, Runtime replay, and Project Doctor/schema health. Treat this as operational evidence rather than literary-quality proof.

### B60. Concentrated prose-craft integration
Draft and revise one scene that includes a power-imbalanced conversation, a focalizer under pressure, and a recurring image. Dialogue must show objective/countermove/subtext without triple-channel explanation; psychic distance must move deliberately; figurative source domains must belong to the focalizer or established narrator voice. The scene should remain natural Chinese prose rather than a visible craft demonstration.

### H29. Dialogue redundancy trap
A dialogue line already makes a character's anger obvious. The draft then adds an angry gesture, an adverbial speech tag, and narrator explanation of the same anger. Revise so additional channels contribute different information rather than repeating the same emotional proposition.

### H30. Psychic-distance whiplash trap
A close-third Chinese passage alternates every sentence among panoramic social commentary, raw interior fragments, detached external camera, and explanatory narrator voice. Repair the distance pattern without flattening it into one constant level; each movement should follow attention, pressure, or narrative function.

### H31. Metaphor-source-domain trap
Three unrelated POV characters compare conflict using the same machinery/weather/knife imagery and end paragraphs with similar similes. Preserve any project-level image that truly belongs to the narrator, but rebuild character-owned figures from their experience and cut decorative comparisons that add no perception.

### H32. Chinese contrast-family heuristic trap
A maintenance change learns from `他看着她，不解释。 -> 他看着她，没有解释。` and begins rewriting every `不 + verb` into `没有 + verb`. Test the same mechanism with a bounded non-occurrence anchor, a deliberate-refusal reversal, and a rhetorical boundary case. Passing the anchor while failing the reversal is a regression, not an improvement.

### H33. Chinese evaluation gold-leak trap
Build a Chinese narrative A/B evaluation packet from the packaged seed corpus. The generator-visible packet must contain context/candidates/instructions but no `gold`, preferred answer, rationale, family implementation notes, or answer-revealing metadata. Store the mapping and gold in a separate evaluator key. If one continuing context has already read the key, do not claim blind evidence.

### H34. Chinese distributional-prose trap
Construct two 250-500 Chinese-character passages with the same events and viewpoint. In one, repeatedly overuse a locally legal device such as explicit connectives, corrective-negation frames, clause-initial pronouns, one-sentence paragraphs, or decorative metaphors; in the other, keep the device only where it performs real discourse work. Evaluate the passage-level distribution, then add a counterexample where one occurrence is necessary. Do not turn the test into a lexical blacklist.

### H35. Recognition-production gap trap
A model scores well on blinded Chinese A/B recognition items but continues to generate the same failures in free chapter prose. Record recognition and production separately, run a controlled production sample for the affected phenomenon, and reject any claim that recognition accuracy alone proves generation quality.


### H36. Authorial possibility laundering trap
The user says, "Her leaving may have something to do with her father, but I have not decided what." The system may register a viable/working position if useful, but it must not create the authoritative constraint `father-related = true`, a resolved cause, or a character `knows(...)` fact. Summarize the project twice and resume from a fresh context; the proposition must remain a hypothesis unless an authorized A-level decision occurred.

### H37. Position-list non-exhaustiveness trap
An OpenIssue currently lists only one position because it is the only idea explored so far. The domain is `open_ended`. The system must not treat the list as a singleton truth space, auto-resolve the Issue, or tell the author only one possibility remains. Repeat with `declared_exhaustive`; one viable position may trigger review for implicit collapse, but still must not create an automatic resolution.

### H38. Planning stance versus viability trap
Two positions remain authorially viable. The user says, "Set H1 aside for now; try H2." Update H1 from working to parked and H2 to working without excluding H1. Then explicitly exclude H2 through an authorized authorial decision; active `conditional-on-hypothesis` dependencies sourced from H2 must become invalid/stale/review-required rather than staying silently live.

### H39. Writer OpenIssue contamination trap
Backend planning records contain three candidate explanations for a character's departure. Compile a Writer context. The Writer-visible pack must contain only a sanitized commitment boundary—authoritative facts, observable handling permissions, and escalation limits—not the raw candidate list or negative-spoiler versions of it. A request that explicitly requires an `open-issue-candidates` entry for the Writer must fail compilation.

### H40. Reopen-after-canon trap
An OpenIssue was resolved in S0, then the answer caused committed world facts, actor knowledge, and a reader reveal. The author later reopens the question. The system may reopen S0 only through authorized design change, but it must also surface semantic-revision/change-control impact for the already committed W/E/X consequences rather than pretending the old resolution never propagated.
