# Project Poetics: Project-Specific Literary Contract

Use this reference when a project must decide **what this particular novel treats as important and how it wants to be experienced**. It is the canonical owner of project-specific literary commitments. It sits between author intent and craft execution.

Project Poetics is planning state, not world truth. It may evolve through explicit user decisions or reviewed discovery, but it must never be inferred silently into canon.

## 1. Core contract

Treat the mapping from project purpose to narrative resources as a rhetorical design problem, not a theme-to-style lookup. This stance is research-informed by rhetorical narratology, while the concrete compiler below is a Skill-specific synthesis [research:phelan-narrative-rhetoric-1996].

Compile the project from:

```text
user intent / theme or question / intended experience / story problem
+ tradition or genre expectations when relevant
+ focalization/world relation / structure-time / formal ambition
+ approved evidence from existing pages
    -> Project Poetics
    -> active poetics capabilities
    -> Narrative Strategy
    -> local craft decisions
```

Do **not** compile `theme -> style preset`.

The same theme may be realized through perception, inquiry, relation, action, memory, social life, argument, ritual, parody, or form. The same formal resource may serve very different themes.

## 2. Inputs

Use only information that is actually available and authoritative:

- user-locked intent and explicit exclusions;
- delegated authorial choices;
- theme/theme question, including `none` or deliberately unresolved theme;
- intended reading experience;
- long-form organizing principle(s);
- project category/tradition/genre when it materially shapes expectations;
- world/reality relation and explanatory threshold;
- focalization/narrator relation;
- structure/time organization;
- formal experimentation level;
- existing approved prose and repeated project-specific patterns;
- user-approved discoveries.

Do not require every input. Theme may be absent. Ending may remain open. A project may begin from voice, relationship, world, problem, image, form, or situation.

## 3. Canonical poetics record

A Project Poetics artifact should answer, in concise natural language:

### Salience
- **What matters?** Which sources may legitimately earn sustained page time?
- **What may remain background?** Which dimensions are present but need not be optimized or foregrounded?

### Reader activity
- **What does the reader mainly do?** Examples: infer, notice, inhabit, compare, wait, remember, judge, doubt, learn a social world, track formal change.
- **What reader knowledge/memory assumptions are safe?**

### Progression
- **What counts as progression here?** Event change, epistemic change, relational accumulation, perceptual reconfiguration, temporal sedimentation, social drift, formal movement, deliberate stasis, or a combination.

### Mind / knowledge
- **How knowable are minds?** Transparent, partially inferential, self-misreading, multiply interpreted, deliberately opaque, variable by character.
- **What is the explanatory threshold?** Which causal/ontological/motivational facts require explanation, and which may remain ordinary, tacit, marvelous, ambiguous, or unavailable?

### Form
- **How visible may form become?** Transparent medium, locally foregrounded, structurally heterogeneous, narrator-visible, formally self-conscious, etc.
- **What repetition/recurrence is licensed?** Habit, ritual, clue, refrain, seasonal return, social routine, stylistic pattern, memory trigger, or other.
- **What unresolvedness is intentional?**

### Protection
- **Do-not-optimize constraints.** Name tempting "improvements" that would damage this project.
- **Authorized deviations.** Record deliberate departures from higher-level voice/structure/selection rules.
- **Active capabilities.** Name only the poetics capabilities needed now; do not activate the whole library.

Do not turn this record into numeric aesthetic weights.

## 4. Scope and inheritance

Poetics can be scoped:

```text
project
  -> arc / volume override
      -> chapter override
          -> scene-local authorized deviation
```

Rules:

- lower scopes inherit higher-scope commitments by default;
- an override must name what it changes and its return/expiry condition when one exists;
- a lower-scope change must not silently rewrite project-level poetics;
- authorized heterogeneity is not drift;
- repeated local deviations may become a **discovery proposal**, not an automatic project-level mutation.

Use the smallest scope that explains the intended variation.

## 5. Capability activation

A capability is available knowledge, not a universal obligation. Activate only when the project needs it.

Examples include:

- thematic polyphony;
- hidden causal networks / adaptive opposition;
- ordinary-life familiarity and recurrence;
- minimalist omission / negative space;
- epistemic puzzle / fair-clue architecture;
- memory-temporality;
- atmosphere/place;
- autonomous social ecology;
- institutional negotiation;
- contingency/noise;
- dynamic vividness;
- figurative/image systems;
- formal heterogeneity;
- retelling/parody logic.

Capabilities may coexist, change scope, or remain inactive.

`Project Poetics` never means `select one style mode`.

## 6. Top-down compilation

### Organizing vocabulary and four independent axes

There is no single universal source of narrative propulsion. **Progression is irreversible change or meaningful accumulation in a project-authorized tracked state.** Such a state may be an option set, hypothesis, social position, relationship, self-model, organization of memory, perception, object relation, interpretive framework, formal pattern, or reader expectation. It need not be runtime world state. Deliberate stasis can earn experience without pretending to be a change.

Use the following as diagnostic vocabulary, never an exhaustive ontology, named-work preset, or exclusive engine enum:

| Organizing family | Sustained pressure / state to track | Specialist execution owner |
|---|---|---|
| Causal / action | Goal, obstacle, choice, counteraction; options, resources, commitments and consequences | `scene-architecture.md` |
| Investigative / epistemic | Evidence, viable alternatives, contradiction, reclassification; observation differs from inference | `reader-model.md`, `knowledge-topology.md` |
| Social / strategic | Ambition, class, access, patronage, reputation; action meaning depends on witness, norm, position and history | `social-transmission-reputation.md`, `institutional-negotiation.md` |
| Relational | Trust, affection, distance, obligation, dependence, shame; dimensions may move in opposite directions | `character-dynamics.md` |
| Subjective / consciousness | Attention, self-report, social mask, self-misreading and contradiction | `character-dynamics.md`, `focalization-narrator.md` |
| Memory / temporal | Sensory activation, association, repeated recollection, retrospective reweighting and return | `narrative-time-duration.md` |
| Perceptual / atmospheric | Body, place, sound, season, duration, absence; familiarity or perception changes | `environment-description.md`, `narrative-selection.md` |
| Obsessive / object-idea | Material object or idea becomes an attention center; relation and meaning accumulate or contradict | `character-dynamics.md`, `figurative-language.md` |
| Metaphysical / interpretive | Support, counter-support, coincidence, failed prediction; a framework's plausibility changes | `open-issue-semantics.md`, `formalization-boundary.md` |
| Formal / polyphonic | Narrator transformation, juxtaposition, competing social languages, perspective collision | `thematic-polyphony.md`, `voice-architecture.md` |

Keep four design questions separate in the existing record:

1. **Organizing**: what sustains attention; what changes or accumulates? Name dominant and supporting principles; leave background dimensions and inactive temptations explicit.
2. **Mediation**: through whose access, retrospect, distance and language does the reader experience it? Focalization and Voice own execution.
3. **Closure / explanation**: which dimensions must close, when and how far; which may remain boundedly open? Investigative organization does not imply openness. A promised unique fair-clue answer must close; atmosphere does not excuse missing observations or operational clarity.
4. **Structural / temporal form**: chronology, episodic cases, associative memory, seasonal recurrence, braided arcs, or other authorized structure. Time and Long Horizon own execution.

The four-axis compiler is **Skill synthesis**, not a scholarly classification or a deterministic schema. Mix principles at project, volume, arc, chapter and scene scope without activating the entire library. `complexity-pruning.md` should remove capabilities that do not support this project's dominant work.

Compile into existing Narrative Strategy and Chapter Mission: the selected contribution, what must change or accumulate, what can remain stable, meaningful recurrence, temporal/focal operations, closure posture, and what generic optimization would destroy the project. Scene-worthiness asks what direct experience contributes, not whether a keyword appears. A dinner may be compressed action logistics, social strategy, self-performance, or relationship duration in different projects.

For drafting readiness, record only consequential unresolved choices in the existing maturity evidence's `draft_dependencies` (see `prewriting-readiness.md`). Do not demand all ten families, numeric literary weights, or a new propulsion artifact.

At project start or major rebuild:

1. read the Project Brief and existing user-locked constraints;
2. state the provisional long-form organizing principle(s);
3. identify intended reader activity and legitimate salience sources;
4. identify tempting but harmful optimizations;
5. activate only capabilities justified by the project;
6. compile Narrative Strategy from these decisions;
7. mark unresolved poetics choices as open/provisional instead of inventing certainty.

A project with `theme: none` can still have valid poetics.

## 7. Bottom-up discovery

Long-form work can discover its own form. When repeated drafting evidence suggests an emergent pattern:

1. record the observation and evidence;
2. distinguish one-off local success from repeated project-level behavior;
3. formulate a poetics hypothesis;
4. test it against user intent, existing commitments, and downstream consequences;
5. require explicit promotion through `discovery-drafting.md` / change control before it becomes authoritative planning state.

Do not auto-promote a stylistic coincidence because it appeared several times.

### Legacy-project neutral bootstrap

An established project may predate the Project Poetics owner. Do **not** infer poetics from genre labels, existing prose, benchmark fingerprints, activated capabilities, or a best-effort reading during representation migration. First migrate the project manifest neutrally; then, only when explicitly requested, run `project_ops.py ensure-poetics` to establish the blank provisional canonical owner.

The bootstrap contract is intentionally narrow:

- create the canonical artifact from the shipped blank Project Poetics template;
- keep `Status: provisional`;
- leave all literary commitments unanswered;
- record manifest provenance with `inference_performed=false`;
- record the representation migration and advance context generation;
- never overwrite an existing canonical Project Poetics artifact;
- never silently adopt an unowned pre-existing file as canonical.

After bootstrap, populate or approve Project Poetics only through normal author/planner decision flow. The existence of a blank owner means **"this project now has a place where poetics decisions belong"**, not **"the Skill has discovered what the poetics are"**.

## 8. Do-not-optimize constraints

These are first-class project decisions. Typical examples:

- do not increase event density merely to "improve pace";
- do not add explicit psychological explanation;
- do not convert ordinary detail into setup/payoff;
- do not force a character arc;
- do not normalize authorized voice variation;
- do not broaden world autonomy beyond the project's chosen focal concentration;
- do not explain marvelous/ambiguous ontology beyond the adopted threshold;
- do not close deliberately open relations/questions;
- do not replace inherited-story play with original-worldbuilding pressure.

Do-not-optimize constraints are not excuses for contradictions. Hard Core still applies.

## 9. Writer-safe derivative

Writers should receive **scoped poetics**, not the full research archive.

A Writer-safe derivative may include:

- active salience sources;
- current progression mode(s);
- reader activity to support;
- mind-opacity / explanatory threshold relevant to the chapter;
- form/voice commitments;
- licensed recurrence;
- do-not-optimize constraints;
- authorized deviations for this scope;
- active capability references.

Do not include hidden future answers merely to explain why a formal choice exists.

Use `context-compilation.md` to include the derivative and only the active capability references needed for the task.

### Thin provenance envelope

Every machine-consumed scoped derivative must travel with a separate provenance envelope governed by `assets/project-schemas/scoped-project-poetics-envelope.schema.json`. The envelope formalizes **only**:

- `authority_ref` - the canonical Project Poetics owner that authorizes this derivative;
- `scope` - project identity plus optional arc/chapter/scene/task selectors;
- `parent_ref` - the immediate planning artifact from which this derivative was compiled;
- `hash.content_sha256` and `hash.parent_sha256` - exact byte identity for the derivative and its parent;
- `status` - `provisional | active | superseded | revoked`; consumers may rely only on `active`;
- `expires_at` - optional timezone-aware expiry.

Do not put salience, progression, voice rules, capabilities, or other literary content into the envelope. The Markdown remains the literary contract; the envelope only proves whether that Markdown is the currently authorized scoped artifact. If the parent hash changes, re-derive and re-authorize rather than silently refreshing the hash.

Use `scripts/scoped_poetics.py` to create/verify the envelope. Context Compiler, Voice Drift authorization, and Writer task validation must reject a bare scoped-poetics path without the matching valid envelope.

## 10. Change control

Treat a Project Poetics change as author-level planning change, not automatic story-state mutation.

Classify changes by scope:

- local authorized deviation - no project-level migration;
- chapter/arc override - scoped downstream invalidation;
- project-level poetics revision - explicit review and affected Narrative Strategy / missions / diagnostics invalidation;
- text-only realization change - no poetics mutation unless the commitment itself changed.

Use `semantic-revision.md`, `change-control.md`, and `project-state.md` for propagation. Preserve provenance of who/what authorized the change.

## 11. Audit

Before approving Project Poetics, ask:

- Is any capability being treated as mandatory simply because the Skill knows it?
- Is a theme being forced into a debate structure it does not need?
- Is a genre label substituting for project-specific reasoning?
- Is "good prose" being treated as one voice profile?
- Are salience/progression rules broad enough for the intended work but narrow enough to guide selection?
- Are do-not-optimize constraints concrete enough to prevent predictable LLM overcorrection?
- Can an authorized local variation be represented without rewriting the whole project?
- Are hard integrity requirements still distinct from aesthetic commitments?
